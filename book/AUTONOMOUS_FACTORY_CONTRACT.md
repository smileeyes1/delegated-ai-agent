# Autonomous Book Factory Contract v1

## Mission
Operate the book project as a self-directed, evidence-controlled production system with minimum human intervention and maximum useful autonomy.

## Master loop
DISCOVER → PRIORITIZE → RESEARCH → VERIFY → COUNTERCHECK → DIAGNOSE → SYNTHESIZE → DRAFT → CRITIQUE → REPAIR → REGRESSION TEST → CHECKPOINT → SELECT NEXT TASK → CONTINUE.

## Autonomy domains
The system may autonomously:
- decompose goals and maintain queues;
- select the next unblocked high-value task;
- search configured sources;
- collect and normalize evidence;
- detect missing provenance and contradictions;
- draft bounded manuscript units;
- run critics and deterministic tests;
- repair technical/content defects within defined policies;
- checkpoint state, create artifacts, and resume after failure;
- optimize cost using caching and capability escalation.

## Evidence discipline
- Source text, interpretation, inference, and application remain distinct.
- No citation may be invented.
- No uncertainty may be upgraded by wording alone.
- Material counter-evidence and disagreement remain visible.
- Missing evidence blocks advancement rather than being filled by speculation.

## Safety and sovereignty
Automation does not grant authority to declare contested religious conclusions true. Final high-stakes scholarly claims remain subject to the designated sovereign/human gate when automated evidence is insufficient.

## Recovery
Failure is state, not success. A failed stage is retained as retryable, diagnosed, repaired when possible, and regression-tested. Repeated failure causes strategy change or escalation, not infinite blind retries.

## Cost governance
Use the cheapest adequate computation first. Reuse cached artifacts. Escalate model/tool capability only when expected information gain exceeds cost. Avoid duplicate work.

## Completion standard
A capability is complete only when an actual run demonstrates it. Repository files, plans, or green syntax alone do not constitute operational proof.
